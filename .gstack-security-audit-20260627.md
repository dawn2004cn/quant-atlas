**Severity**: CRITICAL (confidence: 9/10)  
**File**: `infrastructure/k8s/secrets.yaml` (lines 8-11)  
**Status**: VERIFIED  
**Phase**: 2 — Secrets Archaeology

```yaml
stringData:
  DB_PASSWORD: "quant_service_pass"           # ❌ Plaintext app DB password
  DB_ROOT_PASSWORD: "root_password_change_me" # ❌ Plaintext root DB password
  SECRET_KEY: "change-me-in-production-use-env-var" # ❌ Plaintext Flask secret

```

**Exploit Scenario**:
1. Attacker gains access to Git repository (public mirror, leaked credentials, insider)
2. Reads `secrets.yaml` → obtains DB root password and app password
3. Connects to MySQL as root → dump all user data, trading history, PII
4. Forges Flask session cookies using `SECRET_KEY` → impersonate any user

**Impact**: Full infrastructure compromise, data breach, regulatory fines.

**Recommendation**:
```bash
git filter-repo --force --invert-paths --path infrastructure/k8s/secrets.yaml
kubectl delete secret quant-atlas-secrets -n quant-atlas
kubectl create secret generic quant-atlas-secrets \
  --from-literal=DB_PASSWORD="$(openssl rand -hex 32)" \
  --from-literal=DB_ROOT_PASSWORD="$(openssl rand -hex 32)" \
  --from-literal=SECRET_KEY="$(openssl rand -hex 32)" \
  -n quant-atlas
```

**Playbook**:
1. Revoke leaked credentials immediately
2. Rotate all passwords and API keys
3. Force-push cleaned history
4. Audit exposure window (commit date → removal)
5. Check for abuse in DB audit logs

#### [C-07] Unsanitized LLM output rendered as HTML — XSS Risk

**Status**: VERIFIED

```html
  ).join(''));
  document.getElementById('alertsBody').innerHTML = safeHTML;
</script>
```

Add DOMPurify library and escape user content.

## 📞 Incident Response Playbooks

### For leaked secrets:
1. Revoke the credential immediately
2. Rotate to a new strong password/API key
3. Scrub Git history (`git filter-repo`)
4. Force-push cleaned history
5. Audit exposure window (commit date → removal)
6. Check provider audit logs for abuse

### For database compromise:
1. Take database offline
2. Restore from clean backup
3. Rotate all database credentials
4. Audit all queries for data exfiltration
5. Notify affected users per GDPR/CCPA

### For admin takeover:
1. Lock all admin accounts
2. Rotate JWT secrets
3. Audit all admin actions
4. Re-image admin workstations
5. Notify stakeholders
