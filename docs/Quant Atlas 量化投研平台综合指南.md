Quant Atlas 量化投研平台综合指南
1. 系统架构总览 (Architecture Overview)
Quant Atlas 已从早期的脚本集合演进为 生产级 2.0 分层架构
。该架构严格遵循 SOLID 原则，旨在解决依赖耦合、计算瓶颈和数据一致性问题
。
1.1 核心分层设计
领域层 (Domain Layer)：定义核心模型（如 AlphaEntity, Signal）和抽象端口（Ports），保持业务逻辑纯粹，不依赖框架
。
应用层 (Application Layer)：组织业务用例，如信号生成、组合管理和 AI 诊股，负责编排领域对象和基础设施端口
。
基础设施层 (Infrastructure Layer)：负责持久化（MySQL, SQLite, TimescaleDB）、向量化计算（Rust Core）和第三方数据适配（AKShare, TDX）
。
智能体层 (Agents Layer)：构建基于 LangGraph 的多智能体投研大脑，实现复杂的逻辑推理与决策
。

--------------------------------------------------------------------------------
2. AI 多智能体投研系统 (Multi-Agent System)
这是平台的核心引擎，被定义为“工业级、闭环演进的多智能体投研大脑”
。
2.1 六大专业分析师角色
系统通过 TeamSupervisor 管理四个专业部门，包含 6 个核心分析师节点
：
宏观分析师 (Macro)：分析宏观经济与大盘环境。
基本面分析师 (Fundamental)：解析财报 DTO、研报及行业地位。
技术面分析师 (Technical)：分析价格走势、支撑压力位。
情绪/资金分析师 (Sentiment)：追踪主力资金动向与市场热度。
回测优化师 (Backtest)：执行多策略回测验证结论。
风险经理 (Risk Manager)：对结论进行终审，评估极端情况下的下行风险。
2.2 核心协作机制
证据黑板 (Evidence Blackboard)：Agent 不再传递模糊文本，而是写入强类型的 EvidencePoint（包含键值、置信度、强度），解决长文本幻觉问题
。
分级模型调度 (Tiered LLM)：L1 任务（摘要/过滤）由 GPT-4o-mini 处理，L2 任务（逻辑推演）由 GPT-4o/Claude 处理，最高可节省 60% 成本
。
自动胜率回溯 (Auto-Validator)：后台任务定期比对 Agent 结论与实际股价走势，计算实时胜率并动态调整各 Agent 的决策权重
。

--------------------------------------------------------------------------------
3. 数据流与“本地优先”原则 (Data Flow)
平台推崇 “本地优先” 的数据获取策略，以减少对公网 API 的依赖，提升稳定性
。
3.1 典型数据路径 (A 股)
采集：本地通达信 (lday 文件) → MySQL 分表 (stock_history_sh/sz/...)
。
转换：MySQL 数据 → Qlib CSV → qlib_bin (二进制格式，供研究与回测使用)
。
时序存储：使用 TimescaleDB 处理未复权/复权行情，通过物化视图实现极致的查询性能
。
3.2 数据层选型
SQLite：用于用户配置、自选股、新闻归档及本地行情快照
。
MySQL：作为业务主库，存储用户、资产及按市场分表的历史行情
。
TimescaleDB：专门用于 OHLCV 时序数据的高性能处理
。

熔断与重试：集成 pybreaker 和指数退避重试机制，防止外部 API 故障导致系统雪崩

1. AI 智能体大脑的“神经系统”：证据驱动与自我进化
Quant Atlas 的 Agent 系统不仅是简单的对话接口，而是一个具备结构化认知和闭环学习能力的数字团队。
证据黑板 (Evidence Blackboard) 与强类型通信：系统摒弃了传统的模糊文本传递，引入了 EvidencePoint 模型
。不同 Agent（如基本面或技术面分析师）将发现的支撑位、PE 分位等关键结论写入共享黑板，后续 Agent（如看多/看空辩论者）直接引用这些结构化证据进行逻辑推演，有效解决了 LLM 的长文本幻觉问题
。
反应式路由与早停机制：系统通过 EvidenceRouter 实现智能跳转
。例如，若基本面 Agent 发现个股存在“退市风险”这一核心证据，系统会立即触发早停（Early Exit），跳过昂贵的回测环节，直接由风险经理进行终审，从而显著节省 Token 成本和计算时间
。
元学习闭环 (Meta-Learning)：通过 Auto-Validator 自动回溯器，系统会在 N 天后比对 Agent 结论与真实走势，计算实时胜率（Accuracy Score）
。这些数据会动态反馈到决策层，在最终汇总时调高高胜率分析师的权重，实现决策模型的自我进化
。
2. 高性能基础设施：Rust 引擎与时序存储
为了支撑 5000+ 标的的快速扫描和复杂回测，系统在底层进行了极致的性能工程设计。
Rust 指标引擎 (quant_core)：系统构建了原生 C 扩展，将 SMA、MACD、因子正交化等 CPU 密集型计算下沉到 Rust 层，计算速度较纯 Python 提升了 20-50 倍
。
混合存储阵列：系统采用了精细化的存储方案：
TimescaleDB：专门处理 OHLCV 时序数据，利用其“超表”（Hypertable）和物化视图实现极速聚合查询
。
MySQL 分表架构：按市场（sh/sz/bj/hk/us）对历史行情进行分表存储，解决了单表数据量过大带来的性能衰减
。
Apache Arrow 零拷贝：在处理全市场扫描时，预留了零拷贝计算支持，减少不同进程间的数据传递开销
。
3. 架构的解耦与韧性：从单体到事件驱动
系统已完成从“脚本集合”向“工业级分层架构”的转型，强调稳定契约和异常隔离。
契约化 DTO 与类型安全：全面引入 Pydantic 模型（如 StockQuoteDTO）替代不稳定的 dict 传输，消除了隐式的 KeyError，确保了 API 和内部服务间的数据一致性
。
事件驱动解耦 (Event-Driven)：引入 blinker 总线实现发布-订阅模式
。例如，当数据同步任务完成时，系统发布 DataSyncedEvent，分析服务和风险预警服务会自动感知并触发，而无需在代码中显式相互调用，极大地降低了服务间的耦合度
。
生产级韧性机制：集成了 pybreaker 熔断器，当外部 API（如 FinGPT 或 AkShare）请求受阻时会自动触发保护，防止单个接口故障导致整个系统雪崩
。
4. 业务落地：从工具到“AI 炒股助手”
系统的最终目标是将复杂的量化能力转化为散户可直接操作的产品价值。
诊股报告标准化：将多智能体研究结论封装为标准化的诊股报告，包含一句话结论、产业链位置、三色灯财务预警等直观模块

。
