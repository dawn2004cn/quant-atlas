# Quant-Atlas 全用户频谱功能需求规格书
**文档版本：** v1.0 | **状态：** 待审阅 | **定位：** 产品战略路线图

## 1. 概述
Quant-Atlas 致力于构建一个量化交易操作系统 (Quant OS)。为了实现从“技术领先”到“市场领先”的跃迁，系统必须在保持底层 AI 认知能力的同时，针对不同资金规模、专业程度和合规要求的用户群体，提供分层的功能支撑。

## 2. 用户画像与需求矩阵

### 2.1 散户 (Retail Traders)
**定位：** 追求便捷、低门槛，依赖引导和工具。
**核心痛点：** 缺乏编程能力、缺乏系统化交易知识、情绪化交易。

| 功能模块 | 需求描述 | 预期目标 |
| :--- | :--- | :--- |
| **NL $\rightarrow$ Strategy** | 自然语言直接生成策略逻辑，无需接触代码或复杂模板。 | 实现“所说即所得”的策略构建。 |
| **AI 投资教练** | 基于 `Evidence Graph` 的决策解释，将信号转化为教学过程。 | 提高用户信任度，降低盲目跟风。 |
| **镜像交易 (Copy-Trading)** | 一键订阅 `Alpha Marketplace` 顶尖策略的实时执行。 | 将平台转化为“量化社交”生态。 |
| **心理状态追踪** | 分析手动干预与策略执行的偏差，提供情绪预警。 | 辅助用户建立纪律性交易习惯。 |

### 2.2 量化小团队/精品店 (Quant Boutiques)
**定位：** 追求研发效率、追求边缘 Alpha、对工具链极其敏感。
**核心痛点：** 研发周期长、因子挖掘重复率高、回测速度慢。

| 功能模块 | 需求描述 | 预期目标 |
| :--- | :--- | :--- |
| **自动因子挖掘机** | 引入遗传编程/符号回归，自动化组合算子以发现新因子。 | 将因子发现周期从“周”缩短至“小时”。 |
| **向量化回测引擎** | 实现毫秒级参数扫描（Grid Search），支持超大规模参数空间。 | 极速验证因子有效性。 |
| **另类数据连接器** | 预置情感分析、产业链数据、卫星数据等非结构化接口。 | 提供非共识数据的获取能力。 |
| **协作研究空间** | 共享因子库、研究笔记和回测报告的云端协作环境。 | 提升团队内部的研发协同效率。 |

### 2.3 投资公司/家族办公室 (Investment Companies)
**定位：** 追求资产配置、追求稳健收益、关注跨市场风险。
**核心痛点：** 策略过于单一、缺乏宏观视角、波动率控制不足。

| 功能模块 | 需求描述 | 预期目标 |
| :--- | :--- | :--- |
| **多策略组合优化器** | 基于 $\text{Risk Parity}$ 或 $\text{Black-Litterman}$ 的动态权重分配。 | 优化整体组合的 $\text{Sharpe Ratio}$。 |
| **宏观政体感知引擎** | 将 `MarketRegime` 升级为宏观周期识别（通胀/衰退/牛熊）。 | 实现策略随宏观环境自动切换。 |
| **多资产类兼容** | 扩展至股票、期货、期权、外汇、加密货币，支持跨品种对冲。 | 实现全资产类别的量化覆盖。 |
| **税后收益优化器** | 计算交易税费与滑点，提供最优的税务结转策略。 | 提升实际到手收益率。 |

### 2.4 基金公司 (Fund Managers)
**定位：** 追求绝对合规、追求收益归因、面对监管压力。
**核心痛点：** 收益来源不透明、合规风险高、规模化后的回撤难以控制。

| 功能模块 | 需求描述 | 预期目标 |
| :--- | :--- | :--- |
| **工业级归因分析** | 实现 $\text{Brinson}$ 模型，拆解 $\text{配置贡献} \rightarrow \text{选股贡献} \rightarrow \text{风格暴露}$。 | 为 LP 提供透明、专业的收益报告。 |
| **合规预检系统** | 强制执行单票上限、行业集中度、禁买名单等风控阈值。 | 确保交易行为 100% 符合法律法规。 |
| **决策审计追踪链** | 每一笔交易必须关联一个包含 AI 证据和因子快照的不可篡改记录。 | 通过监管审计，实现责任可溯源。 |
| **主从账户管理** | 支持一个主策略账户同步至数千个子账户，处理资金份额分配。 | 实现资产规模的快速扩张。 |

### 2.5 大型机构 (Large Institutions / Whales)
**定位：** 追求极致执行、追求流动性管理、绝对隐私。
**核心痛点：** 交易冲击成本极高、延迟竞争激烈、数据泄露风险。

| 功能模块 | 需求描述 | 预期目标 |
| :--- | :--- | :--- |
| **冲击成本预测模型** | 基于 LOB (限价单簿) 深度预测大单对价格的实时影响。 | 最小化交易损耗 (Slippage)。 |
| **高级执行算法 (Algo)** | 内置 $\text{VWAP}$、$\text{TWAP}$、$\text{Iceberg}$ 等隐匿下单算法。 | 在不惊动市场的情况下完成大额建仓。 |
| **私有化/联邦部署** | 支持完全离线部署或通过联邦学习更新模型而不交换数据。 | 满足最高级别的金融隐私安全需求。 |
| **极细粒度 RBAC** | 实现研究员、交易员、风控员之间严格的角色权限隔离。 | 消除内部道德风险，确保操作安全。 |

## 3. 战略实施路径 (Roadmap)

为了平衡开发资源与市场获取，建议采取以下三个阶段的升级方案：

### 阶段 I：【流量与生态期】 $\rightarrow$ 聚焦散户与量化团队
*   **重点：** $\text{NL}\rightarrow\text{Strategy}$ $\rightarrow$ $\text{Vectorized Backtest}$ $\rightarrow$ $\text{Copy-Trading}$。
*   **目标：** 通过极低门槛吸引大量用户，在 `Alpha Marketplace` 积累海量因子数据。

### 阶段 II：【专业与信任期】 $\rightarrow$ 聚焦投资公司与基金
*   **重点：** $\text{Multi-Strat Optimizer}$ $\rightarrow$ $\text{Industrial Attribution}$ $\rightarrow$ $\text{Compliance Guardrail}$。
*   **目标：** 建立专业品牌形象，提高客单价，将系统从“工具”升级为“资管基础设施”。

### 阶段 III：【壁垒与规模期】 $\rightarrow$ 聚焦大型机构
*   **重点：** $\text{Market Impact Model}$ $\rightarrow$ $\text{Execution Algos}$ $\rightarrow$ $\text{Federated Deployment}$。
*   **目标：** 构建技术护城河，通过解决规模化交易的极致痛点，进入最高端市场。

---

## 4. 技术影响预估
为实现上述功能，底层架构需在以下方面进行升级：
1.  **接口层**：增加 $\text{WebSocket}$ 实时推送流，支持 $\text{Tick}$ 级数据交互。
2.  **计算层**：引入 $\text{Polars}$ 或 $\text{VectorBT}$ 等高性能向量化计算库。
3.  **安全层**：引入 $\text{RBAC}$ 权限系统与基于 $\text{Hash}$ 的审计日志链。
4.  **部署层**：开发容器化私有部署方案 (K8s / Docker) 以支持机构用户。
