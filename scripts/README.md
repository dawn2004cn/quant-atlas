# scripts 目录说明

`scripts/` 是历史与辅助目录，不是当前主平台的主代码入口。

## 当前定位

这里的内容主要分为三类：

1. 运维与迁移脚本
   例如数据初始化、缓存巡检、数据库迁移、历史补数。
2. 实验性脚本
   例如一次性策略验证、数据源试验、临时分析。
3. 历史遗留入口
   早期原型或旧实现，保留用于参考，不建议作为新功能落点。

## 团队约定

- 当前主平台入口是仓库根目录的 `run.py` 和 `app/`。
- 新功能默认写入 `app/` 与 `tests/`。
- 如果某个脚本仍承担生产职责，应逐步迁移到 `app/tasks/`、`app/application/services/` 或明确的运维目录。
- 新增脚本时，请在文件头或文档里注明用途、输入、输出和是否仍被生产依赖。

## 建议的后续整理

- 将脚本逐步按 `ops/`、`migrations/`、`experiments/` 分类。
- 给仍在使用的脚本补状态标签，例如“保留”“待迁移”“可归档”。
- 避免把新的长期业务逻辑继续累积到 `scripts/`。

## 目标目录

- `scripts/ops/`
  放运维、巡检、只读诊断类脚本。
- `scripts/migrations/`
  放数据库、缓存和历史数据迁移脚本。
- `scripts/experiments/`
  放研究性和试验性脚本。
- `scripts/candidates/`
  放暂不进入主平台链路、但也不准备直接归档的候选脚本。

更细的迁移批次见 `docs/SCRIPTS_MIGRATION_PLAN.md`。
